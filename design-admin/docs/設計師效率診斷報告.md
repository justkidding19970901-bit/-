# MonnaCase 墨盾｜設計師作業流程效率診斷報告

> 版本：v1（2026-06）｜對象：設計部（1 位設計師）+ 主管
> 目的：統合設計部、提升單一設計師的產出效率。本報告先盤點現況、鎖定瓶頸、提出對策，並指出哪些對策會被做進「KPI/庶務控管系統」成為天天可用的工具。

---

## 0. 一頁總結（TL;DR）

設計部目前由**一位設計師**扛起：每月 4 款獨家手機殼、商品圖合成、電商上架圖/詳情頁，外加**六日夜市擺攤**。在這個負荷下，效率損耗集中在兩個地方：

| # | 瓶頸 | 性質 | 核心對策 | 預期效益 |
|---|------|------|----------|----------|
| 1 | **上架圖 / 詳情頁每次重排** | 重複勞動 | 詳情頁**模組化版型庫** + 上架圖**固定規格批次匯出** + 上架前**檢查清單** | 每款詳情頁從「重排」變「換圖填字」，估省 50–70% 排版時間 |
| 2 | **夜市占掉設計工時** | 結構性超載 | **產能緩衝庫**（離峰備稿）+ 夜市素材一次做齊重用 + 用系統**可視化「夜市工時 vs KPI」**讓主管調目標/排班 | 把每月被夜市吃掉的 ≈8 個工作天攤平，避免月底趕工 |

工具面（PS/AI + AI 生圖 + Procreate）已具備加速條件，差在**標準化**與**範本化**還沒建立。下面逐項說明。

> 標示慣例：✅=已確認事實　🔶=依現有資訊的推估，需設計師確認

---

## 1. 流程現況盤點

一款設計從無到上架，目前的路徑：

```
原創設計            白底商品圖          商品圖合成           電商素材               上架
(Procreate/AI/PS) → (去背/打光白底) → (情境圖、套用畫面) → (上架圖+詳情頁排版) → (16 Pro / 17 Pro)
```

✅ 已確認：
- 工具組合：**Adobe PS/AI + AI 生圖工具 + Procreate 手繪**。
- 商品圖**只需做 iPhone 16 Pro / 17 Pro 兩機型**，流程是先有**白底圖**，再做**商品圖合成**。
- 月 KPI 基準：**4 款獨家手機殼**；另希望每月多做 **1 款可抽成圖像**。
- 需支援**六日夜市**。

🔶 待設計師確認的耗時分佈（先用推估，之後用系統實測校正）：

| 環節 | 推估單款耗時 | 重工程度 |
|------|------------|----------|
| 原創設計（含發想） | 高 | 低（創意本體，難壓縮也不該壓縮） |
| 白底商品圖 | 中 | 中（可範本化、AI 輔助） |
| 商品圖合成（情境） | 中 | 中（情境背景可建風格庫重用） |
| **上架圖/詳情頁排版** | **高** | **高（每款重排 → 最大可壓縮空間）** |

> 結論：**創意環節不要壓**，要壓的是**排版與重複輸出**這種「重工」。下面兩節針對兩大瓶頸。

---

## 2. 瓶頸一：上架圖 / 詳情頁每次重排

### 問題
每款新設計都重新排一次上架主圖與詳情頁長圖。即使版面結構其實高度重複（主視覺、設計理念、規格、認證、CTA…），仍以「從頭排」的方式做，導致：
- 重複勞動、時間拉長；
- 版面不一致（字級、間距、色塊每款略有差異），品牌調性鬆散；
- 來回補圖（少一張情境、規格寫錯）造成上架延誤。

### 對策 A：詳情頁**模組化版型庫**（最關鍵）
建立一套固定區塊的詳情頁範本，用 **PS 智慧物件**或 **Figma 元件**，新款只需「換主圖 + 換文案」，不再重排版面。

建議固定區塊（順序可調）：
1. 主視覺 Hero（設計主圖）
2. 設計理念 / 故事（這是墨盾日系・廟宇民俗的賣點，務必固定欄位）
3. **機型對應**（16 Pro / 17 Pro）
4. **SGS 軍規防摔認證**（信任區塊，固定圖卡）
5. 規格表（材質、防摔等級、孔位、重量）
6. 情境圖 / 細節圖
7. CTA（加入購物車 / 門市 / 夜市資訊）

> 做法：把每個區塊做成可替換的智慧物件 / 元件；主圖、文字、情境圖設為「外掛」圖層。新款 = 連點替換。

### 對策 B：上架圖**固定尺寸規格表 + 批次匯出**
把 16 Pro / 17 Pro 所需的所有圖檔尺寸列成固定規格表，搭配 **PS 動作（Action）/ Export As 預設**一次匯出。避免每款手動另存、改尺寸、命名。

> 規格表會直接做進系統的「上架圖規格對照」頁（交付物 2），設計師匯出時一眼對照。

### 對策 C：詳情頁**上架前檢查清單**
固定一份 checklist，上架前逐項勾選（主圖到位、理念文案、規格正確、認證圖、兩機型圖齊、命名規範…），降低來回補圖。

> 此清單做進系統的「詳情頁檢查清單」頁（交付物 2）。

### 預期效益
詳情頁從「重排」變「換圖填字」，估**省下 50–70% 排版時間**，且版面一致、品牌更穩。

## 3. 瓶頸二：夜市占掉設計工時

### 問題（量化）
六日擺攤 → 一個月大約**少掉 8 個工作天**的設計產能，但 KPI（4 款 + 商品圖 + 電商圖）並未對應調整 → **結構性超載**，容易月底趕工、品質與抽成圖（獎勵）被犧牲。

這不是「設計師不夠快」，而是**工時與目標沒有對齊**。靠純技巧壓縮治標不治本，要從**時間配置**與**可視化**著手。

### 對策
1. **產能緩衝庫（備稿庫）**：離峰時提前備 1–2 款手機殼草稿/半成品，讓夜市週也有東西可上，削平月底高峰。
2. **深度設計時段集中**：把需要連續專注的原創設計，排在**非夜市日**的整段時間；零碎日處理排版、匯出、回覆。
3. **夜市素材一次做齊重用**：展示卡、海報、POP、價目表做成**可重用範本**，不要每次擺攤重做。
4. **可視化「夜市工時 vs KPI」**：用控管系統把「本月夜市出勤次數 ≈ 損失工時」和「KPI 達成率」**並排呈現**，讓主管看見取捨，據此**調目標或調排班**（例如夜市旺季把月 KPI 從 4 調為 3，或夜市與設計輪替）。

> 第 4 點是這份報告與控管系統的接點：系統的價值不只是記錄，而是**讓超載被看見、可被管理**。

---

## 4. 工具加速建議（PS/AI + AI 生圖 + Procreate）

1. **AI 生圖用在對的地方**：
   - 白底 → 情境圖：用**生成填色 / 背景延展**快速產出情境背景，建一個**情境風格庫**（日系、廟宇、簡約棚拍…）重複套用。
   - ⚠️ 原創殼面圖案仍以手繪/原創為主，AI 僅輔助背景與情境，避免品牌原創性被稀釋。
2. **PS 標準化**：智慧物件範本 + 批次動作（去背、打光、匯出）。
3. **檔名 / 版本 / 資料夾規範**：固定命名（如 `款名_機型_用途_版本`）與資料夾結構，降低「找檔 / 認版本」的隱形成本（這也是「上架圖/詳情頁重排」之外常被低估的時間黑洞）。

## 5. 落地清單：建議 → 系統功能對照

報告不只是建議，下列項目會做進「KPI/庶務控管系統」變成天天可用的工具：

| 報告建議 | 對應系統功能 |
|----------|--------------|
| 對策 C 詳情頁檢查清單 | **詳情頁上架前檢查清單**頁 |
| 對策 B 上架圖固定規格 | **16 Pro / 17 Pro 上架圖規格對照**頁 |
| 瓶頸二第 4 點 可視化取捨 | **Dashboard：夜市工時 vs KPI 並列** |
| 產能緩衝庫 | 產出可標「備稿中」狀態，主管看緩衝量 |
| 月 KPI 對齊夜市 | 主管可**逐月調整 KPI 目標** |

---

## 6. 下一步 / 需設計師確認

為了把推估換成實測、把對策調到最貼合，請設計師確認：
1. 各環節實際單款耗時（可先用系統記錄 2–4 週）。
2. 詳情頁目前固定/常變的區塊各有哪些（用來定版型庫）。
3. 上架圖實際需要的所有尺寸清單（16 Pro / 17 Pro）。
4. 夜市每次實際占用時數與頻率（用來算損失工時）。

> 確認後即可把版型庫、規格表、KPI 目標填成正式值，本報告會出 v2。
